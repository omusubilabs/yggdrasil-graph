# Internationalization

This repository is English-first and structured so that adding a language is a
translation job, not an engineering one.

**Post-v1 targets:** Icelandic (`is`), Norwegian Bokmål (`nb`), Swedish (`sv`),
Danish (`da`), Finnish (`fi`), Japanese (`ja`). All six are declared in routing
and in the locale registry from day one; `en`, `ja`, `fi`, `is`, `nb` and `sv`
are `complete`, and `da` remains `planned`.

---

## How it is laid out

```
src/i18n/
├── config.ts                  locale registry: list, status, endonyms, direction
├── index.ts                   t(), useTranslations(), localePath()
└── locales/
    ├── en/
    │   ├── ui.json            interface chrome
    │   ├── entities.json      entity.<id>.{epithet,summary,description}
    │   └── relations.json     relation.<type>.{label,inverse,phrase}, family.*
    ├── ja/
    │   ├── ui.json            complete
    │   ├── entities.json      complete — every id en covers
    │   └── relations.json     complete — every type en covers
    ├── fi/
    │   ├── ui.json            complete
    │   ├── entities.json      complete — every id en covers
    │   └── relations.json     complete — every type en covers
    ├── is/
    │   ├── ui.json            complete
    │   ├── entities.json      complete — every id en covers
    │   └── relations.json     complete — every type en covers
    ├── nb/
    │   ├── ui.json            complete
    │   ├── entities.json      complete — every id en covers
    │   └── relations.json     complete — every type en covers
    └── sv/
        ├── ui.json            complete
        ├── entities.json      complete — every id en covers
        └── relations.json     complete — every type en covers
```

Routing is Astro's, configured in `astro.config.mjs` with
`prefixDefaultLocale: false`. English is at `/`, everything else is prefixed:

| Locale | Home  | Entity page       |
| ------ | ----- | ----------------- |
| `en`   | `/`   | `/entity/loki`    |
| `ja`   | `/ja` | `/ja/entity/loki` |
| `fi`   | `/fi` | `/fi/entity/loki` |
| `is`   | `/is` | `/is/entity/loki` |
| `nb`   | `/nb` | `/nb/entity/loki` |
| `sv`   | `/sv` | `/sv/entity/loki` |

Every page emits `lang` and `dir` on `<html>`, a canonical URL, `hreflang`
alternates for every locale that has content, and an `x-default` pointing at
English.

## Using it in a component

```astro
---
import { useTranslations } from '../i18n/index.ts';
const t = useTranslations(Astro.props.locale);
---

<h2>{t('panel.relations')}</h2>
<p>{t('graph.selectedAnnounce', { name: 'Loki', count: 9 })}</p>
```

Lookup falls back to `en` **key by key**, not file by file, so a partial locale
renders its own strings where it has them and English where it does not. A key
that resolves nowhere returns the key itself — loud enough to catch in review,
and it never leaves a blank where a sentence should be.

`t.has(key)` tells you whether the current locale has a real value, which is how
entity pages decide between rendering a description and rendering the
"no account written yet" line.

### No hardcoded user-facing strings

Every string a person can read or hear goes through `t()`.
`npm run check:strings` walks `src/components`, `src/pages`, `src/layouts` and
`src/graph`, and fails the build on:

- text nodes in `.astro` templates, outside tags, `{expressions}`, `<style>`,
  `<script>` and comments;
- static values of perceivable attributes — `aria-label`, `alt`, `title`,
  `placeholder` and friends;
- assignments to `textContent`, `innerText`, `title`, `ariaLabel`, and
  `setAttribute()` calls targeting a perceivable attribute.

The escape hatch is an `i18n-ignore` comment on the same line or the line before:

```astro
{/* i18n-ignore: Old Norse name, data from data/entities/ */}
<span class="non">{node.names.non}</span>
```

Use it only for genuine non-text: a close glyph, a language code, or a string
that came out of `data/` and is therefore identical in every language.

### What is deliberately _not_ translatable

- **`names.non`** — the Old Norse form is the historical name, identical in
  every locale. It is data, and it lives in `data/entities/`.
- **Work titles in `sources.json`** — same reasoning. _Gylfaginning_ is
  _Gylfaginning_ everywhere.
- **Language endonyms** in `config.ts` — a switcher that shows "Japanese" to an
  English reader and "日本語" to a Japanese one is a worse switcher.

## The browser runtime

`src/graph/runtime.ts` contains no text at all. It never composes a sentence; it
looks one up from the payload fetched at mount.

That payload is `/graph/<locale>.json`, prerendered by
`src/pages/graph/[locale].json.ts`, and it carries the graph plus exactly the
keys the runtime asks for — listed explicitly in `RUNTIME_KEYS` so the payload
cannot quietly grow into a copy of the whole locale file.

If you add a string to the runtime, add its key to `RUNTIME_KEYS` in the same
change, or it will render as a raw key in production.

## Locale states

Declared in `src/i18n/config.ts`, and they determine what `npm run i18n:check`
demands:

| Status     | Meaning                          | Checker requires                                   |
| ---------- | -------------------------------- | -------------------------------------------------- |
| `source`   | `en`. Defines the key structure. | —                                                  |
| `complete` | Fully translated.                | Every key `en` has. A missing key fails the build. |
| `partial`  | Deliberately incomplete.         | No keys `en` lacks. No empty strings.              |
| `planned`  | No files yet.                    | No locale directory to exist.                      |

The asymmetry is intentional. **Missing keys are measured debt** — the fallback
chain handles them and the checker reports coverage. **Extra keys are always a
bug**: either a typo, or a string that exists in one language and nowhere else,
and both rot silently.

The checker also:

- diffs `{placeholder}` sets per key, because a translation that drops `{name}`
  loses data at runtime and no key-set comparison would catch it;
- rejects empty-string values — omit the key instead and let the fallback work;
- rejects the same key defined twice across a locale's files;
- cross-checks `astro.config.mjs` against `config.ts`, so a locale can never end
  up with routes and no strings, or strings and no routes.

### Why `ja` ships incomplete

A placeholder locale proves nothing; a genuinely partial one exercises the
fallback chain, font loading, `lang` attribute, and hreflang alternates for
real.

## Adding a locale

1. Promote it in `src/i18n/config.ts`:

   ```ts
   export const LOCALE_STATUS: Record<Locale, LocaleStatus> = {
     en: 'source',
     ja: 'partial',
     is: 'partial',   // was 'planned'
     …
   };
   ```

2. Create `src/i18n/locales/is/` and copy `ui.json` from `en`, translating
   values. Translate keys you are confident about and **omit the rest** — do not
   ship empty strings.

3. Add the bundle to `BUNDLES` in `src/i18n/index.ts`. It is a static map rather
   than a glob on purpose: a missing file is then a type error at build time
   instead of an empty object at runtime.

4. Add the routes. Each locale needs page files under `src/pages/<locale>/` that
   pass `locale` down to the shared view components — see `src/pages/ja/` for the
   pattern. Three files: `index.astro`, `sources.astro`, `entity/[id].astro`.

5. Run the checks:

   ```bash
   npm run i18n:check
   npm run build
   ```

6. Check the typography (below) before opening the pull request.

## Typography

Every face this site ships must render the Old Norse orthography —
`þ ð æ ø ǫ ę ǿ á é í ó ú ý` and their capitals — at every weight and style used.

`npm run check:glyphs` verifies this by opening the shipped font binaries and
reading their character maps. It does **not** trust `unicode-range`, which only
says which subset file a browser should fetch and promises nothing about what is
inside it.

Two things that check taught us:

- **`þ ð æ ø` are in the `latin` subset**, not `latin-ext`; `ǫ ę ǿ` are in
  `latin-ext`. Coverage is only sound as the union of both.
- **IBM Plex Mono has no `ǫ` or `Ǫ`.** It was the first choice for the citation
  apparatus and would have put tofu in the middle of _Vǫluspá_, _Mjǫllnir_,
  _Jǫrmungandr_ and _Skǫll_. Source Code Pro is here because it passed.

If a locale needs a script the Latin faces do not cover, follow the Japanese
pattern:

- put its `@font-face` imports in a **separate stylesheet**
  (`src/styles/fonts-ja.css`), imported only by that locale's pages, so the
  bundler cannot ship it to any other route;
- override `--font-ui` and `--font-display` under a `[lang="xx"]` selector,
  keeping the Latin display face **first** in the display stack so Old Norse
  names keep their serif and their diacritics;
- prefer the **sliced** `@fontsource` build for CJK. The monolithic Japanese
  subset is roughly a megabyte per weight; the sliced variable build splits the
  same coverage across ~120 narrow unicode-ranges, so a reader downloads tens of
  kilobytes instead;
- add the package to `MANIFEST` (or the equivalent block) in
  `scripts/check-glyphs.ts`. The script cross-checks its manifest against the
  `@fontsource` imports actually present in `src/`, so an unlisted font is a
  build failure rather than an unchecked one.
